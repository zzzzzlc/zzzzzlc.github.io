# 常见企业系统与解决方案：从 OA 到 ERP 的全景选型指南

## 一、问题来源

企业信息化建设中，最常遇到的不是技术难题，而是"不知道要什么"：

**认知层面的痛点：**

- 听说过 OA、ERP、CRM、MES，但不清楚它们的边界在哪，一个需求到底属于哪个系统
- 老板说"我们要上 ERP"，但团队不确定 ERP 是否解决了当前最紧迫的问题
- 市面上有大量开源/商业/SaaS 方案，不知道选哪个，选错了切换成本极高

**实施层面的痛点：**

- 买了一套 ERP，发现只用了 10% 的功能，其余 90% 成为负担
- 自研了一套 OA，做到一半发现需求覆盖不全，继续投入还是采购成品？
- 多个系统数据不通：销售在 CRM 录了客户，财务在 ERP 又录一遍
- 不知道什么时候该用低代码平台，什么时候该自研

**核心问题：企业系统选型不是"选一个最好的"，而是"选一个适合当前阶段的"。需要理解各系统的定位、核心模块、数据流转关系，才能做出合理的决策。**

## 三、OA 办公自动化

### 3.1 业务定位

```
OA（Office Automation）= 企业日常办公的基础设施

核心价值：
- 将线下纸质流程搬到线上（请假、报销、采购申请）
- 统一企业内部沟通渠道（公告、通知、会议）
- 积累企业知识资产（文档管理、知识库）

适用企业：几乎所有企业都需要（通常是第一个上线的系统）
```

### 3.2 核心模块

```
┌──────────────────────────────────────────┐
│                OA 系统                    │
├──────────────┬───────────────────────────┤
│ 流程审批     │ 请假/报销/采购/用章/出差  │
│              │ 自定义表单 + 审批流        │
├──────────────┼───────────────────────────┤
│ 公告通知     │ 企业公告/部门通知          │
│              │ 已读/未读/确认机制          │
├──────────────┼───────────────────────────┤
│ 日程会议     │ 日历/会议室预定/会议纪要   │
├──────────────┼───────────────────────────┤
│ 文档管理     │ 文档上传/版本管理/权限控制 │
│              │ 在线预览/协同编辑          │
├──────────────┼───────────────────────────┤
│ 通讯录       │ 组织架构/员工信息/外部联系人│
├──────────────┼───────────────────────────┤
│ 考勤管理     │ 打卡/外勤/加班/出差统计    │
├──────────────┼───────────────────────────┤
│ 任务协作     │ 任务分配/进度追踪/工作汇报 │
└──────────────┴───────────────────────────┘
```

### 3.3 方案对比

| 类型 | 代表产品 | 优点 | 缺点 | 适用 |
|------|---------|------|------|------|
| 商业 SaaS | 钉钉/飞书/企业微信 | 开箱即用、生态丰富 | 定制受限、数据在外部 | 中小企业 |
| 商业私有化 | 泛微/致远/蓝凌 | 功能全面、可定制 | 价格高、实施周期长 | 大中型企业 |
| 开源自研 | Odoo/Directus/NocoDB | 完全可控、免费 | 需要技术团队维护 | 有研发能力的团队 |

## 四、ERP 企业资源计划

### 4.1 业务定位

```
ERP（Enterprise Resource Planning）= 企业资源的统一调度中心

核心价值：
- 打破部门信息孤岛（销售/采购/库存/财务数据打通）
- 统一数据源（一个产品信息只在 ERP 维护一份）
- 流程标准化（采购到付款、销售到收款全链路规范化）

适用企业：制造业、贸易公司、连锁零售等有库存和供应链管理需求的企业
不适用：纯互联网公司、轻资产服务公司（这些公司更需要 CRM/OA）
```

### 4.2 核心模块与数据流转

```
                    ┌──────────┐
          ┌────────→│  销售管理 │←──────────┐
          │         │ 报价/订单 │            │
          │         └─────┬────┘            │
          │               │ 销售订单        │
          │               ▼                │
     ┌────┴────┐   ┌──────────┐   ┌────────┴───┐
     │  客户   │   │  库存管理 │   │   财务管理  │
     │  管理   │   │ 入库/出库 │   │ 应收/应付  │
     └─────────┘   │ 库存盘点 │   │ 总账/成本  │
                   └─────┬────┘   └──────┬─────┘
                         │               │
                    ┌────┴────┐          │
                    │  采购管理│──────────┘
                    │ 请购/询价│ 采购发票
                    │ 订单/入库│
                    └────┬────┘
                         │
                    ┌────┴────┐
                    │ 供应商  │
                    │  管理   │
                    └─────────┘

核心数据流：
1. 销售订单 → 扣减库存 → 生成发货单 → 确认收入 → 应收账款
2. 采购申请 → 采购订单 → 收货入库 → 增加库存 → 应付账款
3. 生产领料 → 扣减库存 → 生产入库 → 增加库存 → 成本归集
```

### 4.3 方案对比

| 类型 | 代表产品 | 特点 | 价格 |
|------|---------|------|------|
| 国际商业 | SAP / Oracle | 功能最全面、制造业标杆 | 百万~千万级 |
| 国内商业 | 用友/金蝶 | 本土化好、财务合规 | 十万~百万级 |
| 开源 | Odoo / ERPNext | 模块化、社区活跃 | 免费（实施收费） |
| 行业垂直 | 各种行业 ERP | 深耕特定行业 | 视行业而定 |

### 4.4 ERP 实施的常见坑

```
1. 大而全陷阱
   → 想一步到位覆盖所有业务 → 项目失控
   → 正确做法：先上核心模块（财务+库存），再逐步扩展

2. 业务流程改造 vs 软件适应业务
   → "按 ERP 的标准流程来" vs "ERP 要适配我们的流程"
   → 正确做法：核心流程向标准看齐，特殊流程保留定制

3. 数据迁移
   → 老系统的数据质量差 → 直接导入新系统会出问题
   → 正确做法：先做数据清洗，分批迁移+校验

4. 用户抵触
   → 新系统改变了工作方式，一线员工不愿用
   → 正确做法：分阶段培训，关键用户参与测试，灰度上线
```

## 五、CRM 客户关系管理

### 5.1 业务定位

```
CRM（Customer Relationship Management）= 从线索到回款的全客户生命周期管理

核心价值：
- 销售过程可视化（线索 → 商机 → 报价 → 成交）
- 客户信息集中管理（不再散落在 Excel 和微信里）
- 销售业绩可预测（漏斗分析、业绩预测）

适用企业：有销售团队的企业（B2B 为主）
不适用：纯线下门店/无销售团队的企业
```

### 5.2 核心模块

```
┌──────────────────────────────────────────────┐
│                 CRM 系统                      │
├───────────────┬──────────────────────────────┤
│ 线索管理      │ 线索收集/清洗/分配/转化       │
│               │ 来源：官网/展会/400/推荐      │
├───────────────┼──────────────────────────────┤
│ 客户管理      │ 客户画像/联系记录/附件        │
│               │ 客户分级/跟进计划             │
├───────────────┼──────────────────────────────┤
│ 商机管理      │ 销售漏斗/阶段推进/赢单率      │
│               │ 预计金额/成交概率/预计日期    │
├───────────────┼──────────────────────────────┤
│ 报价/合同     │ 产品报价/合同模板/电子签章    │
├───────────────┼──────────────────────────────┤
│ 销售目标      │ 团队/个人目标/完成率/排行     │
├───────────────┼──────────────────────────────┤
│ 数据分析      │ 漏斗分析/转化率/业绩报表      │
│               │ 来源分析/客户分布             │
└───────────────┴──────────────────────────────┘
```

### 5.3 方案对比

| 类型 | 代表产品 | 适用 |
|------|---------|------|
| 国际 SaaS | Salesforce / HubSpot | 大型企业/跨国公司 |
| 国内 SaaS | 销售易/纷享销客/探马 | 中大型 B2B 企业 |
| 轻量 SaaS | Pipedrive / Monday | 小型销售团队 |
| 开源 | Dolibarr / Twenty | 有定制需求的技术团队 |

## 八、MES 制造执行

### 8.1 业务定位

```

MES    → "怎么做"（工序执行、数据采集、质量管控）
设备层 → "执行"（数控机床、PLC、传感器）

┌────────┐  生产计划   ┌─────┐  工艺指令  ┌──────┐
│  ERP   │───────────→│ MES │──────────→│ 设备 │
│        │←───────────│     │←──────────│      │
│        │  完工报告   │     │  生产数据  │      │
└────────┘            └─────┘            └──────┘
```

```
┌──────────────────────────────────────────────┐
│                 MES 系统                      │

├───────────────┼──────────────────────────────┤
│ 生产执行      │ 工序报工/条码追溯/异常报警    │
```

## 十、系统间的数据流转

### 10.1 核心数据实体归属

```
哪个系统是哪个数据的"主数据源"：

┌──────────────┬────────────────────────────────────┐
│   主数据     │              归属系统              │
├──────────────┼────────────────────────────────────┤
│ 组织架构     │ HRM（或统一身份平台）               │
│ 员工信息     │ HRM                                │
│ 客户信息     │ CRM                                │
│ 产品/物料    │ ERP                                │
│ 供应商       │ SCM                                │
│ 项目信息     │ PM                                 │
│ 合同信息     │ ERP / CRM（看合同类型）             │
│ 财务科目     │ ERP（总账）                        │
└──────────────┴────────────────────────────────────┘

原则：一个数据只在一个系统中维护（单一数据源）
其他系统通过接口同步或引用
```

### 10.2 典型数据流转场景

```
场景 1：销售到交付全链路

CRM（销售签单）→ ERP（创建销售订单）→ SCM（发货）
    → ERP（确认收入/应收）→ FMS（开发票/收款）

场景 2：采购到付款全链路

ERP（采购申请）→ SCM（询价/下单）→ SCM（收货）
    → ERP（入库/应付）→ FMS（付款）

场景 3：招聘到离职全链路

HRM（发布职位）→ HRM（面试/Offer）→ HRM（入职）
    → OA（开通账号/权限）→ ERP（创建员工主数据）
    → HRM（考勤/薪酬）→ HRM（离职/交接）

场景 4：生产计划到完工

ERP（生产计划）→ MES（工单下达）→ MES（工序执行/质检）
    → MES（完工报告）→ ERP（入库/成本核算）
```

## 十一、选型决策：自研 vs 采购 vs 低代码

### 11.1 三种路径对比

```
┌──────────┬────────────────┬────────────────┬────────────────┐
│   维度   │     自研       │     采购成品    │    低代码平台   │
├──────────┼────────────────┼────────────────┼────────────────┤
│ 定制程度 │ 完全定制       │ 有限定制        │ 中等定制       │
│ 初期成本 │ 高（开发人力） │ 中（许可/实施） │ 低             │
│ 长期成本 │ 中（维护）     │ 高（年费/升级） │ 中（平台费）   │
│ 上线周期 │ 3~12 个月      │ 1~6 个月        │ 1~3 个月       │
│ 技术要求 │ 高（需要研发） │ 低（需要运维）  │ 低（业务人员） │
│ 数据主权 │ 完全自主       │ 取决于供应商    │ 取决于平台     │
│ 灵活性   │ 最高           │ 最低            │ 中等           │
│ 适用规模 │ 大型/特殊需求  │ 通用需求        │ 中小型/快速验证│
└──────────┴────────────────┴────────────────┴────────────────┘
```

### 11.2 决策树

```
需求是否标准化（和行业通用流程一致）？
├── 是 → 采购成熟产品
│        ├── 预算充足 → 商业方案（SAP/用友/金蝶/飞书）
│        └── 预算有限 → 开源方案（Odoo/ERPNext）
│
└── 否 → 需求是否特殊到没有合适产品？
         ├── 是 → 自研（或基于开源深度定制）
         │        ├── 有研发团队 → 自研
         │        └── 无研发团队 → 外包 + 验收
         │
         └── 否 → 有一些特殊需求但大部分通用
                  ├── 核心业务 → 采购 + 定制开发
                  └── 非核心业务 → 低代码平台搭建
```

### 11.3 各系统推荐路径

```
┌────────┬──────────────────────┬────────────────────────┐
│  系统  │     推荐路径         │        原因             │
├────────┼──────────────────────┼────────────────────────┤
│  OA    │ 采购 SaaS（飞书/钉钉）│ 标准化程度高，没必要自研│
│        │ 或低代码              │                        │
├────────┼──────────────────────┼────────────────────────┤
│  ERP   │ 采购商业/开源        │ 财务合规要求高，自研风险│
│        │ （非制造业可低代码）  │ 极大，不建议自研       │
├────────┼──────────────────────┼────────────────────────┤
│  CRM   │ 看复杂度             │ 标准销售流程 → 采购    │
│        │                      │ 特殊业务 → 自研/低代码 │
├────────┼──────────────────────┼────────────────────────┤
│  HRM   │ 采购 SaaS            │ 社保/个税/考勤合规性强 │
│        │                      │ 自研容易出合规问题     │
├────────┼──────────────────────┼────────────────────────┤
│  SCM   │ 采购行业方案         │ 行业差异大（制造/零售）│
│        │                      │ 选深耕行业的供应商     │
├────────┼──────────────────────┼────────────────────────┤
│  MES   │ 采购 + 定制          │ 需要对接设备层         │
│        │                      │ 行业 know-how 比代码重要│
├────────┼──────────────────────┼────────────────────────┤
│  PM    │ 轻量用 SaaS          │ Jira/飞书项目/Linear   │
│        │ 特殊用低代码         │ 覆盖大部分需求         │
└────────┴──────────────────────┴────────────────────────┘
```

## 十二、企业信息化演进路径

### 12.1 分阶段实施建议

```
阶段 1（0~1 年）：办公基础
  └── 上 OA（飞书/钉钉/企业微信）
      → 审批流程线上化
      → 企业通讯录
      → 即时通讯/会议

阶段 2（1~2 年）：核心业务
  └── 上 ERP（财务 + 库存）
      → 统一财务数据
      → 库存管理规范化
      └── 可选：CRM（如果有销售团队）

阶段 3（2~3 年）：业务深化
  └── 按行业深化
      → 制造业：MES + SCM
      → 服务业：CRM + 项目管理
      → 连锁零售：SCM + POS

阶段 4（3~5 年）：数据驱动
  └── BI 数据分析
      → 各系统数据打通
      → 经营驾驶舱
      → 辅助决策

阶段 5（5 年+）：智能化
  └── AI 赋能
      → 智能审批建议
      → 销售预测
      → 需求预测
      → 异常预警

原则：
- 不要跳阶段（没有 ERP 就上 MES 是空中楼阁）
- 先有数据再谈分析
- 先标准化再自动化
```

### 12.2 常见失败原因

```
1. 贪大求全
   → 一期就要上全部模块 → 超期/超预算/烂尾
   → 正确做法：分期实施，每期 3~6 个月

2. 重技术轻管理
   → 只关注系统功能，不改变管理流程
   → 系统上线了但没人用，或者用错了
   → 正确做法：系统实施 = 30% 技术 + 70% 管理

3. 忽视数据质量
   → 老数据不清洗直接导入 → 新系统输出错误数据
   → 正确做法：上线前做数据治理，统一编码规范

4. 缺少变革管理
   → 员工习惯了老系统/Excel，不愿意切换
   → 正确做法：关键用户参与、分批培训、新旧并行过渡

5. 选型只看功能
   → 功能多但不匹配业务 → 僵化/定制贵
   → 正确做法：先梳理业务流程，再选匹配的系统

6. 忽视集成
   → 各系统独立运行 → 数据孤岛
   → 正确做法：规划统一数据架构，预留接口
```

## 十三、局限性与边界

```
本文的局限：

1. 行业差异巨大
   - 本文覆盖的是通用模块
   - 制造业/金融/医疗/教育各有特殊系统
   - 选型必须结合行业特点

2. 方案持续迭代
   - SaaS 产品更新快，功能和价格可能已变化
   - 开源项目活跃度也会变化
   - 选型前需要做最新的市场调研

3. 实施比选型更难
   - 选对产品只成功了一半
   - 实施过程需要业务部门深度参与
   - 供应商的实施能力比产品功能更重要

4. 组织因素 > 技术因素
   - 企业系统成功的关键不是技术
   - 而是管理层的支持、流程的标准化、用户的接受度
   - 最先进的系统也无法弥补混乱的管理

5. 总拥有成本（TCO）
   - 许可费只是冰山一角
   - 实施/定制/集成/培训/运维/升级都需要投入
   - 选型时要算 3~5 年的总成本
```
